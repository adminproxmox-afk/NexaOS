# Архитектура NexaOS 0.2

```text
Браузер
  ├─ Диспетчер загрузки → профиль, питание, RAM, полноэкранный режим
  └─ v86 / WebAssembly
       ├─ NexaOS → bzImage + rootfs.cpio.gz
       │            └─ /init → BusyBox init → getty → login → ash
       │                                         ↕
       │                                  UART COM1 / xterm.js
       └─ Демонстрационный ISO → BIOS → CD-ROM → Linux → VGA / PS/2
```

Диспетчер читает файлы по HTTP, проверяет формат образов и компилирует WebAssembly перед созданием VM. Он запускает процессор после `emulator-ready`. Для NexaOS готовность подтверждают баннер init и `nexaos login:` на COM1. Для исходного ISO критерием служит видимое приглашение `/root%` в VGA. Веб-код передаёт клавиши и отображает гостевой вывод.

v86 0.5.473 при прямой загрузке размещает initramfs с адреса 64 МиБ. Для таких профилей доступны 128, 256 и 512 МиБ. Диспетчер проверяет, помещается ли архив в выбранный объём памяти. Профиль ISO дополнительно допускает 64 МиБ.

Ранняя инициализация ядра выполняет `/init` из cpio. Скрипт монтирует devtmpfs, proc, sysfs, tmpfs и devpts, затем заменяет себя BusyBox init с PID 1. `/etc/inittab` задаёт начальный скрипт для hostname и баннера, а также возобновляемый getty на `ttyS0`. `login` открывает shell от UID 1000 в `/home/user`. Buildroot поставляет musl, BusyBox и дерево `/bin`, `/boot`, `/dev`, `/etc`, `/home`, `/lib`, `/proc`, `/root`, `/sbin`, `/sys`, `/tmp`, `/usr`, `/var`.

Холодная перезагрузка освобождает экземпляр v86 и создаёт новый. Завершение из браузера выполняется на уровне VM. Согласованное выключение изнутри гостя, ACPI и синхронизация будущего диска требуют отдельной интеграции. У NexaOS выключен IP-стек, у v86 отсутствует сетевой мост. Последовательная консоль предназначена для локального тестового сеанса.

Если v86 после сбоя не подтверждает остановку, диспетчер показывает ошибку и предлагает обновить страницу. Перезагрузка страницы освобождает оставшиеся ресурсы.

## Подключение диска

Ядро собрано с драйвером ATA PIIX, SCSI disk и ext4. Следующий этап передаст дисковый образ через поддерживаемый v86 параметр `hda` и добавит процедуру определения и монтирования раздела из гостя. Initramfs останется загрузочной средой. Стратегия хранения должна учитывать сброс кэшей гостя, версию и геометрию образа и восстановление после прерванной записи. См. [API v86](https://github.com/copy/v86/blob/master/v86.d.ts).

## Гостевой Desktop

NexaDesktop будет самостоятельной программой Linux. Первый графический запуск должен проверить VGA/VESA, PS/2, доступ к VT и X.Org на этой конфигурации. Следующий слой реализует обработку событий оконного менеджера X11, раскладку рабочего стола и запуск приложений через процессы Linux. Веб-диспетчер сможет отобразить VGA-сеанс и передавать ввод через v86, сохраняя отдельный путь диагностики через COM1.
