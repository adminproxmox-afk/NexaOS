# Архитектура NexaOS 0.3

```text
Диспетчер загрузки в браузере
  ├─ v86 / WebAssembly → bzImage + initramfs → BusyBox init
  │    ├─ COM1 → getty → login → ash
  │    ├─ COM2 → служба управления ext4
  │    ├─ ATA /dev/sda → ext4 /home/user
  │    └─ Bochs DRM → X.Org modesetting → гостевой xterm → VGA
  └─ IndexedDB → последний подтверждённый образ /dev/sda
```

Диспетчер читает файлы по HTTP, проверяет формат образов и компилирует WebAssembly перед созданием VM. Он запускает процессор после `emulator-ready`. Готовность NexaOS подтверждают приглашение `nexaos login:` и ответ дисковой службы через COM2. Профиль X.Org дополнительно ждёт успешного подключения X11-клиента. Для исходного ISO критерий готовности остаётся приглашение `/root%` в VGA.

v86 0.5.473 размещает initramfs с адреса 64 МиБ. Для прямой загрузки доступны 128, 256 и 512 МиБ. Профиль ISO также допускает 64 МиБ. У NexaOS выключен IP-стек, у v86 отсутствует сетевой мост.

Ранняя инициализация выполняет `/init` из cpio, монтирует devtmpfs, proc, sysfs, tmpfs и devpts, затем передаёт PID 1 BusyBox init. Для штатных профилей init проверяет метку `NEXADATA` и монтирует весь виртуальный диск `/dev/sda` в `/home/user` с `nosuid,nodev`. Учётная запись UID 1000 владеет корнем этого тома.

## Сохранение ext4

Скрипт сборки создаёт пустой ext4-образ на 64 МиБ. Загрузчик берёт сохранённую копию из IndexedDB либо пустой образ при первом запуске. Для подключения используется параметр `hda` v86. Закреплённая версия v86 оборачивает переданный `ArrayBuffer` и пишет сектора в него. Один Web Lock на адрес сайта защищает диск от параллельной записи из двух вкладок. См. [API v86](https://github.com/copy/v86/blob/master/v86.d.ts) и [реализацию буфера](https://github.com/copy/v86/blob/315b2b0b758703ef0e6cc7b4088d6068f83f3c20/src/buffer.js).

При выключении или перезапуске служба COM2 выполняет `fsfreeze`. Ядро сбрасывает изменения ext4 и приостанавливает запись. Диспетчер ждёт ответ с номером запроса и записывает диск одной транзакцией IndexedDB. После подтверждения транзакции он освобождает VM. При ошибке записи служба снимает заморозку, чтобы можно было повторить сохранение. Принудительное выключение после ошибки оставляет последний сохранённый образ.

Данные привязаны к профилю браузера и адресу сайта, включая протокол, хост и порт. После сбоя или закрытия вкладки до подтверждения сохранения следующий запуск возьмёт последний зафиксированный образ. Очистка данных сайта удаляет эту копию. Остальные каталоги гостя живут в RAM.

## Первый сеанс NexaDesktop

X.Org запускается в Linux на VT1. Драйвер modesetting использует Bochs DRM, а evdev принимает события эмулируемых PS/2-устройств. Начальный сеанс содержит xterm от имени `user` и использует тот же ext4-диск. Локальное подключение X11 защищено cookie, сетевой сокет X.Org отключён. Браузер отображает VGA и позволяет переключиться на COM1. Журналы запуска хранятся в `/var/log/nexa-desktop.log` и `/var/log/Xorg.0.log`.

Следующий графический этап включает оконный менеджер X11, рабочий стол и запуск гостевых приложений. Диагностический канал COM1 остаётся отдельным от графики.
